## The web-timeout bug specifically

`src/channels/web.c:54` had `#define WEB_REQUEST_TIMEOUT 600  /* must
cover multi-step delegation chains */`. This was a per-request HTTP
server-side timeout that fired regardless of `max_turn_secs`,
returning a 504 to smolswarm even when the in-flight LLM turn would
have finished a minute later.

Pre-`0ac28bf` timeout chain:

1. **smolclaw web channel: 600s (hardcoded)** ← fires first
2. smolclaw `max_turn_secs`: configurable (default 300s + grace)
3. smolswarm curl `--max-time`: derived from researcher's
   `max_turn_secs` + 30s grace (defaults to 900+30 if unset)

So even with `max_turn_secs=1200` set on the researcher, the web
channel killed the connection at 600s and the workflow saw "Request
timed out" with `state_json.research = {"error":"Request timed out"}`.

Post-`0ac28bf`:

```
agents.defaults.max_turn_secs = 1200   # one knob
  ↓
smolclaw web channel timeout = 1230s   # auto-derived in manager.c
smolclaw turn budget = 1200s + grace
smolswarm curl --max-time = 1230s      # reads same field from generated config
```

A power user can still override the web timeout independently with
`channels.web.request_timeout_secs`.
