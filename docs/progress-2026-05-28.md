# Progress 2026-05-28

## Summary

Two commits today on smolclaw, both supporting the cross-repo Phase 5
(per-turn tool-workspace narrowing) initiative. The Stage-4 routing
decision from the prior session-isolation work is now regression-tested,
and `gateway_process_message` accepts and honors an optional
`run_repo_dir` on inbound messages so delegate tools get scoped to the
run-specific repo checkout for one turn at a time.

## Changes

### `0456ff1` — `test(session-isolation): lock in gateway routing decision`

Locks in the Stage-4 follow-up fix (`7226204` from the prior session)
that routes isolated messages through `sc_agent_process_isolated`.
Approach mirrors the existing `sc_web_compute_isolation` pattern:
extracted a one-line decision helper into a new tiny header so it can
be unit-tested without dragging in the full agent.

- `src/gateway_route.h` (new) — `sc_gateway_should_isolate(msg)`
  inline helper. Returns 1 iff `msg->isolated && msg->namespace_id &&
  msg->namespace_id[0]`; defensive against NULL/empty.
- `src/main.c::gateway_process_message` — uses the helper instead of
  the inline condition. No behavior change.
- `tests/test_gateway_routing.c` (new) — 8 cases covering the truth
  table + a bus round-trip that proves `sc_inbound_msg_t` carries
  `isolated`/`namespace_id` through `publish_inbound`/`try_consume_inbound`
  intact.
- `CMakeLists.txt` — registers the new test.

### `d505af8` — `feat(gateway): per-turn tool-workspace narrowing (Phase 5, smolclaw side)`

Adds optional `run_repo_dir` on `sc_inbound_msg_t`. When set and safe,
`gateway_process_message` swaps the tool registry's workspace to
`<agent->workspace>/<run_repo_dir>` for the duration of one turn, then
restores it. Tools that gate on `restrict_to_workspace` (`read_file`,
`list_dir`, `exec`, `exec_bg`, `git`) see only the run-scoped
checkout — the model can no longer browse stale workspace state via
`list_dir`. `agent->workspace` is untouched so memory consolidation
and the scratchpad still write to the agent-wide path.

- `src/bus.h`, `src/bus.c` — new `run_repo_dir` field on
  `sc_inbound_msg_t`; `sc_inbound_msg_new` signature extended; freed
  in `sc_inbound_msg_free`.
- `src/gateway_route.h` — added `sc_gateway_run_repo_dir_safe(p)`
  helper: rejects NULL/empty/absolute, bare `..` segments
  (segment-aware so `runs/abc..def` passes), and paths >1024 bytes.
- `src/main.c::gateway_process_message` — swap/restore around the
  agent call; mirror of `tools/worktree.c`'s pattern. `stat()` catches
  a missing dir at runtime; an invalid value logs a WARN and falls
  through to the full workspace.
- `src/channels/web.c` — parses `run_repo_dir` from the POST body and
  passes it to `sc_inbound_msg_new`.
- `src/channels/base.c`, `src/main.c` cron dispatch — updated to pass
  NULL `run_repo_dir`.
- `tests/test_gateway_routing.c` — extended from 8 cases (44
  assertions) covering the safety-helper truth table plus a bus
  round-trip preserving `run_repo_dir`.
